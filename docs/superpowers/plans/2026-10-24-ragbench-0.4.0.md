# RAGBench 0.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. The user runs this plan **one task at a time** ("implement task N"). Read §0–§4 first, then only your task. Each task is a brief: before coding, expand it into steps (superpowers:writing-plans) against the code as it is then.
>
> **Marking progress (every executor):** when you finish your task and its acceptance criteria are verified, mark it done in this file before your final message. Add a line directly under the task heading: `**Status:** ✅ Done YYYY-MM-DD · <one-line outcome, plus any deviation or follow-up for later tasks>`. Do not mark a task done if its acceptance is unmet or unverified; write `**Status:** 🚧 Partial · <what is left>` instead. Read the `Status` lines of the tasks you depend on before starting.

**Goal:** Take RAGBench from *"compare the RAG pipelines we ship, on your data"* to *"benchmark **any** RAG solution, agentic RAG or agent harness on your data, with any frontier or open-weight model, trust the numbers, and **improve** the winner automatically"*, and publish a real benchmark on a real public dataset in the repo. Three pillars:

1. **Trustworthy measurement**: repeated trials, independent judge panels, pairwise judging, claim-level faithfulness, held-out splits.
2. **Benchmark anything**: HTTP endpoints, Python callables, LangChain / LlamaIndex / Haystack, CLI agent harnesses (Claude Code, Codex, OpenCode), and any model through OpenRouter (GLM, Kimi, MiMo, DeepSeek, Qwen, MiniMax, ...), next to the built-in systems.
3. **Contrastive Harness Optimization** (ported from Harness², see §2): from static pipeline evaluation to a Propose → Probe → Compose loop that edits a system's harness (prompts, guardrails, tool guidance, knobs) using behavioral contrasts between runs, verified on a held-out split.

**Tech stack:** Python ≥3.11, Typer, Pydantic v2, pandas/numpy, Jinja2, OpenAI SDK, optional extras, all on their latest releases (Task 1). New optional extras only: `langchain`, `llamaindex`, `haystack`, `otel`, `mcp`.

## 1. Findings: what is holding the project back

State on 2026-10-24 (`main` @ `a08921c`, 0.3.0 + `decision_gate`): ~22k lines of source, 84 test files, `ruff`, `mypy` and the full pytest suite pass, coverage floor 90%. The engineering is strong (registries, typed configs, tracing, cache, resume, bootstrap + Holm, Pareto, recommendation). The gaps are in reach, credibility of the headline numbers, and what the tool can be pointed at.

### Credibility of the results

- **F1. The bundled benchmark does not discriminate, and there is no real-dataset result.** In the README example 18 of 24 systems are statistically tied with the best answer score, on a 23k-token synthetic corpus. No published run on a public dataset exists. → Tasks 11, 12, 26.
- **F2. The headline judge is the generator.** `gpt-6-luna` both answers and judges in the published example; the self-preference warning fires on our own README. Only pointwise 0–5 scoring exists, with no judge-agreement or human-calibration number. → Tasks 2, 7, 8.
- **F3. Intervals ignore system randomness.** Each question is answered once; agentic systems are stochastic, so a ranking can flip on a re-run and the CI does not show it. No pass@k / pass^k. p95 latency rests on a 5-question probe. → Task 6.
- **F4. Faithfulness and relevance are coarse.** Relevance is document-level; faithfulness is one judge axis; refusals are detected by wording heuristics. → Task 9.
- **F5. No held-out split.** Nothing separates "tune on" from "report on", which every tuning feature needs. → Task 10.

### Reach: what can be benchmarked

- **F6. Only built-in systems can be benchmarked.** No HTTP endpoint, Python-callable or framework adapter. → Tasks 13, 14.
- **F7. Agent harnesses are out of reach** (Claude Code, Codex, OpenCode). → Task 15.
- **F8. Prompts are hard-coded** (`models/prompts.py`, agent prompts). → Task 19.
- **F9. Roadmap items still open:** MCP tools, GraphRAG, dashboard. → Tasks 16, 17, 25.

### Models, dependencies, adoption

- **F10. Not installable from PyPI, no tagged releases.** `pip install ragbench` 404s (the name is **free**); `git ls-remote --tags` is empty; `.dockerignore` exists but there is no Dockerfile. → Task 3.
- **F11. Name collision** with Galileo's 2024 RAGBench dataset (arXiv 2407.11005, `rungalileo/ragbench`). → Tasks 3, 11.
- **F12. No positioning** against RAGAS / ARES / TruLens / DeepEval / promptfoo, no docs site. → Tasks 25, 27.
- **F13. `evaluation/evaluator.py` is a 1,022-line orchestrator.** → Task 5.
- **F14. Slow and loose dev loop.** Full pytest ~8 min; mypy `check_untyped_defs = false`; the `jev` decision backend only raises. → Task 4.
- **F15. Stale models and prices.** The price table (`models/cost.py`) predates Claude Haiku 5.5 (released 2026-10-07, $0.10 / $0.50 per 1M tokens, a tenth of Haiku 4.5's $1 / $5), and the default independent judge is still `claude-haiku-4-5`. Prices that depend on prompt length (Haiku 5.5 is $0.50 / $2.50 above 100k prompt tokens) cannot be expressed. → Task 2.
- **F16. Open-weight models are second-class.** OpenRouter works only as a generic `openai_compatible` endpoint: no price sync, no real billed cost (`usage.cost`), no reasoning-token control (the recent open models are reasoning models; uncontrolled thinking tokens bill as output), no provider pinning for reproducibility. → Task 2.
- **F17. Dependencies are behind.** On 2026-10-24: `anthropic` 2.3.0 (floor `>=1.10`, a major behind), `twine` 7.0.0 (`>=6`), `ruff` 0.17.2 (`>=0.16`), `mypy` 2.4.0, `openai` 3.37.0 (`>=3.22`), `pandas` 3.1.0, `numpy` 2.5.4, `pydantic` 2.14.1, `faiss-cpu` 1.15.1, `qdrant-client` 1.20.0, `sentence-transformers` 6.2.0, `pypdf` 6.21.2, `pre-commit` 4.7.0; `actions/upload-artifact@v6` → v7.0.2 (open Dependabot branch `dependabot/github_actions/actions/upload-artifact-7`), `actions/setup-python` v7.1.0, `actions/checkout` v7.0.1; pre-commit hooks `ruff-pre-commit` v0.16.9 → v0.17.2, `mirrors-mypy` v2.3.1 → v2.4.0. → Task 1.

## 2. Harness² (google-research/harness2), and what to port

**What it is.** A framework for *recursive agent harnessing*: model weights stay fixed and the **harness** (system prompt, guardrails, memory, tool guidance, subagents, skills, scripts, plugins: an editable component tree `c1..c8`) is what gets optimized, per task, without ground truth.

| Mechanism | Harness² | Port to RAGBench as |
| --- | --- | --- |
| Editable surface | `tree.py`: a typed component tree, validated, diffed; edit contract is *omitted-is-inherited* | Task 19: a `harness:` surface per system, patch semantics |
| Evidence as files | `context.py`: `task.md`, `rollouts/<label>.md` (full trajectories), `deliverables/`, `harness/`, `library/`, `MISSION.md`; the prompt is a short pointer | Task 21: an evidence directory built from traces and contrast sets |
| Propose → Probe → Compose | `recursion.py`: `k` base rollouts; `k` **INV** (general) + `k` **DOM** (domain) candidates; each probed; `k` compositions merge the pool using behavioral contrasts | Task 22: `ragbench optimize` |
| Two modes | *parallel* (width) and *sequential* (depth) | Task 22: `--mode parallel|sequential --k K` |
| Budget identity | `ledger.py`: R = 4k rollouts, P = 3k proposer stages, asserted; invalid proposal gets one retry, then inherits | Task 22: ledger + `estimate` support |
| Selection without labels | `selection.py`: anonymized candidates (seeded shuffle), a selector picks one; failure falls back to base | Task 8 (pairwise/arena judging), reused by Task 22 |
| Experience library | `library.py`: per-domain, time-ordered; adopted harness + *evidence-supported lesson* | Task 23 |
| Leakage tripwires | `assert_no_grader_verdicts`, `leak_globs`, prompts forbidden from saying "benchmark / score / rubric" | Tasks 10, 21 |
| Method/judge separation | judge failure is `None`, excluded from the denominator | Already true (missing ≠ zero); a rule for the optimizer |
| Run identity | `runmark.py`: harness fingerprint | Already `checkpoint.context_hash`; add the harness hash (Task 19) |
| Collapse check | `tree.diversity`: pairwise line-Jaccard | Task 22 |
| Substrates | OpenCode / Codex executors | Task 15: `cli_agent` |
| Credential-free demo | `harness2-demo` | Task 22: `ragbench optimize --mock` |

**Where RAGBench should differ:** Harness² refines per task with no ground truth. RAGBench has a dataset, so it can optimize on a train split and **prove** the gain on a held-out split with its paired bootstrap. That is the selling point of 0.4.0.

## 4. Live-run budget: $25–27 for the whole release, and when to top up

**What things cost** (measured on the 7 Oct example run, then scaled): all 24 systems cost **$0.020 per question** with `gpt-6-luna` generating and judging; on larger corpora expect **~$0.034/question** for ~26 systems. Ingestion is **~$0.7–3.5 per 1M corpus tokens**, mostly `contextual`. `claude-haiku-5-5` as the independent judge costs the same as `gpt-6-luna` ($0.10 / $0.50), **but above 100k prompt tokens it is 5× dearer**, and the judge reads what the generator read, so `full_context.context_token_budget` must stay **≤ 50k** in paid runs. Recent open-weight models are reasoning models: run generation and judging with reasoning off or low (Task 2), or output cost explodes. The cache makes repeats almost free; `trials: 1` in paid runs (Task 6 is verified in mock).
