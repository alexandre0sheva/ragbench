# Error Code Reference

Every RAGBench Mutual service returns a stable error code. Prefixes identify the service: `HS` for HarborShield AI, `CP` for ClaimPilot, `AR` for Aurora Risk Suite, `BP` for the Broker Portal.

| Code | HTTP status | Meaning | Recommended action |
| --- | --- | --- | --- |
| HS-4127 | 413 | Submission packet exceeds the maximum packet size. | Split the packet or compress scanned pages. |
| HS-4130 | 415 | Unsupported file type in the packet. | Convert the file to PDF, DOCX, or TXT. |
| HS-4202 | 503 | The sanctions list snapshot is stale and was not refreshed in time. | Retry after the next scheduled refresh; contact support if it persists. |
| HS-4219 | 422 | The vessel route could not be parsed from the packet. | Add a route summary page or set the route fields manually. |
| CP-2201 | 422 | The loss notice text is longer than the maximum notice length. | Attach the long document instead of pasting it into the notice body. |
| CP-2310 | 504 | The queue-routing adapter timed out while contacting the claims system. | ClaimPilot retries twice automatically; escalate after the third failure. |
| CP-2377 | 409 | A notice with the same external reference already exists. | Use the existing notice or supply a new external reference. |
| AR-3308 | 400 | The export would exceed the row cap for the customer's plan. | Narrow the filters or ask the workspace admin about a higher plan. |
| AR-3342 | 403 | The user lacks access to the requested Scenario Board. | Ask the board owner to share it. |
| BP-5001 | 400 | The `X-Tenant-Id` header is missing from the request. | Add the tenant header; it is mandatory on every call. |
| BP-5044 | 429 | Too many requests: the per-key rate limit was exceeded. | Back off and retry after the number of seconds in the `Retry-After` header. |
| BP-5090 | 500 | Unexpected internal error. | Retry once, then open a support ticket quoting the `request_id`. |

## Notes

Codes are never reused. A retired code is marked as retired here but stays in the table, so old logs remain decodable.

Support must quote the code and the `request_id` from the response body in every ticket about an API failure.
