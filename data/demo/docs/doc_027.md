# ClaimPilot Routing Configuration

ClaimPilot reads its routing rules from a YAML file stored per tenant. This page shows the default configuration shipped with ClaimPilot 2.4 and explains the feature flags that change routing behavior.

```yaml
routing:
  auto_escalation_confidence: 0.75
  default_queue: standard
  queues:
    fnol_fast:
      max_severity: low
      target_first_touch_minutes: 15
    standard:
      max_severity: medium
      target_first_touch_minutes: 60
    complex:
      max_severity: high
      target_first_touch_minutes: 120
    litigation:
      keywords: ["attorney", "lawsuit", "subpoena"]
      target_first_touch_minutes: 30
  max_notice_chars: 40000

flags:
  FF_ROUTE_V2: true
  FF_SPANISH_NOTES: true
  FF_SIU_PREFILTER: false
```

## Feature flags

`FF_ROUTE_V2` switches ClaimPilot to the second-generation router, which scores the notice text and the attached documents together instead of the notice text alone. It is enabled by default from ClaimPilot 2.2 onward.

`FF_SPANISH_NOTES` enables the Spanish-language adjuster note template. It was added in ClaimPilot 2.4 and is on by default.

`FF_SIU_PREFILTER` runs a cheap fraud-indicator check before routing and sends notices with three or more red flags straight to the SIU queue. It is off by default because it is still being piloted with two customers.

## Changing a rule

Edit the YAML, run `claimpilot validate-routing`, and deploy through the normal configuration pipeline. Routing changes take effect within 5 minutes and are written to the audit log.
